Flow-of-Funds Tracer v2 · multi-asset

Each wallet keeps a separate pool per asset, in native units. Intra-wallet swaps move the victim allocation between pools; cross-wallet hand-offs and bridges carry it between wallets. One accounting method governs every pool in the trace.
Accounting method
Applied per asset pool across the entire trace; switching recomputes everything live. LIBR is shown per pool as a ceiling only.
Mixed hand-offs
FIFO/LIFO only: how a single part-victim transfer is consumed when a withdrawal boundary splits it. Proportional treats one transfer as homogeneous — a single transaction has no internal chronology. Ordered sub-lots stacks the victim portion beneath the clean portion (legacy convention).

Ledgers run in native units per asset. A swap or bridge carries the victim allocation across assets by its fraction of the transfer: victim out of the source pool is computed under the selected method, and victim into the destination = amount received × (victim carried ÷ amount sent) — fees and slippage reduce victim and clean funds pro-rata. Mixed hand-off treatment (FIFO/LIFO): 'proportional' books each part-victim transfer as one homogeneous lot — a single transaction has no internal chronology, so any amount drawn from it carries its victim fraction. 'Ordered sub-lots' books the victim portion beneath the clean portion; per-withdrawal splits under that convention are convention-dependent whenever a withdrawal boundary falls inside a mixed transfer (aggregates are unaffected). The active treatment is recorded in the export header. Edited victim figures are flagged as analyst overrides and appear as such in the export. The USD price table is a reporting overlay only.
CSV import format (per wallet): header type,asset,amount,tag,ref,date · type = deposit|withdrawal · tag = victim|other (deposits only; default other) · rows are appended in file order, so ensure the file is chronological · # lines are skipped.
